# FORGE — от бизнес-задачи до проверяемого задания

FORGE помогает бизнесу сформулировать практическую задачу для AI Sana, а командам — понять требования и предложить решение. Вместо публикации сырого текста платформа проводит автора через AI-интервью, показывает конкретные пробелы в постановке, собирает версионированный Task Pack и проверяет его готовность к передаче команде. Решение рассчитано на заказчиков задач, команды-исполнители и организаторов хакатона.

Это рабочее веб-приложение, а не статичный макет: аккаунты и роли, сохранение данных, каталог, отклики, админ-панель и управление ими работают через FastAPI и SQLite. Демо-записей при запуске не создаётся. OpenAI подключается серверным ключом; без ключа доступны честно обозначенные вопросы на основе правил, но AI-функции не имитируются.

## Что реализовано

- Регистрация и вход с ролями **бизнес**, **команда** и **администратор**; доступ к действиям ограничен ролью и владельцем записи. Самостоятельная регистрация администратором запрещена.
- Админ-панель: сводка пользователей, задач и предложений, назначение ролей, журнал изменений ролей, учёт AI-вызовов, входящих/кэшированных/исходящих токенов и оценка затрат в USD.
- Кабинет бизнеса: создание черновика из свободного описания, редактирование, ответы на уточняющие вопросы, оценка готовности, Task Pack, Handoff Test, публикация и рассмотрение откликов.
- AI-разбор исходного описания в структурированные поля с цитатами-источниками; AI-интервью задаёт вопросы по самым важным пробелам. Предложения AI не становятся подтверждёнными фактами без действия пользователя.
- **Readiness Compiler:** детерминированные ошибки и предупреждения, статус сборки, следующая рекомендуемая правка и официальная оценка до 100 баллов. Слабую задачу можно опубликовать с явными предупреждениями.
- **Task Pack:** семь секций с содержимым, статусом и источником сведений; редактирование и подтверждение полей; история ответов; версия карточки увеличивается после содержательных подтверждённых изменений.
- **Handoff Test:** пять проверок, достаточно ли карточки для передачи другой команде. Правила работают без AI; при наличии ключа добавляется независимая AI-проверка только подтверждённой карточки. Результат остаётся советом, а не гарантией успеха.
- Публичный каталог с поиском и фильтрами, карточка опубликованной задачи, профиль команды, отклик с планом, сроком, прототипом и вопросами.
- Кабинет бизнеса для сравнения откликов и ручного решения; уведомление команды о статусе и баллы за подтверждённую работу. Победитель не выбирается алгоритмом.
- Адаптивный интерфейс на русском языке: понятный маршрут создания задачи, тёмная объёмная визуальная система, оригинальные изображения, состояния пустых списков, загрузки и ошибок.

## Как работает решение

1. Бизнес регистрируется и описывает проблему обычным текстом. Черновик сохраняется в базе.
2. Если настроен OpenAI API, сервер извлекает из текста предполагаемые поля и источники. Автор проверяет и подтверждает их. Затем он отвечает на приоритетные вопросы интервью. Без ключа интерфейс показывает вопросы по правилам и прямо сообщает, что это не AI.
3. Компилятор оценивает только подтверждённые поля и показывает, что мешает передаче задания команде. Автор дополняет семь секций Task Pack, указывает доступ к данным, критерии приёмки и ответственность за проверку.
4. Handoff Test проверяет готовность карточки. Автор видит оставшиеся риски и публикует задачу, даже если некоторые предупреждения остаются.
5. Команда ищет задачу в каталоге, читает Task Pack и отправляет предложение. Бизнес сравнивает предложения и вручную принимает или отклоняет их.

## Оценка и диагностика

Официальный балл Readiness Compiler считается на сервере без AI. Поля должны быть подтверждены автором:

| Критерий | Баллы |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Желаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Компилятор возвращает коды ошибок `E01–E07` для отсутствующих критичных сведений и предупреждения `W02–W07` для уточнений и рисков. Статус сборки (`failed`, `warning`, `success`) отражает полноту задания, а не качество будущего решения. Список диагностик и следующий шаг видны в кабинете. Баллы и статусы нельзя повысить простым AI-ответом без подтверждения человека.

Task Pack состоит из семи секций: описание задачи, стартовые данные, ожидаемый результат, критерии готовности, первые шаги, взаимодействие, риски и ограничения. Для каждого пункта интерфейс показывает, подтверждён ли он, и происхождение сведений: исходный текст, ответ, ручная правка или AI-предложение. Сервер хранит историю ответов и версию карточки.

Handoff Test проверяет пять условий: понятность проблемы, проверяемость результата, доступность данных, критерии приёмки и определённость передачи результата. При подключённом AI он может добавить независимые замечания; окончательные правила и статус остаются вычисляемыми и воспроизводимыми.

## Технологии и архитектура

| Слой | Технологии | Назначение |
| --- | --- | --- |
| Интерфейс | Nuxt 4, Vue 3, TypeScript, CSS | Кабинеты, редактор, каталог, отклики, админ-панель |
| API | Python, FastAPI, Pydantic | Авторизация, бизнес-правила, AI-вызовы |
| Хранение | SQLite | Пользователи, задачи, ответы, предложения |
| AI | OpenAI Python SDK, Responses API, структурированный вывод | Разбор описания, интервью, независимый Handoff-review |

`app/pages/index.vue` связывает основные пользовательские сценарии. Компоненты `app/components/ReadinessCompiler.vue`, `TaskPackEditor.vue`, `HandoffPanel.vue` и `AdminPanel.vue` отвечают за диагностические, редакторские и административные блоки. Тёмная тема находится в `app/assets/rebrand.css` и `app/assets/polish.css`; оригинальные WebP-изображения — в `public/forge-hero.webp` и `public/forge-flow.webp`. FastAPI-маршруты находятся в `backend/main.py`; правила оценки — в `backend/domain.py`, компиляция Task Pack и Handoff — в `backend/compiler.py`, обращения к OpenAI и журнал фактических токенов — в `backend/ai.py`, миграции и доступ к SQLite — в `backend/storage.py`.

Браузер общается только с FastAPI. `OPENAI_API_KEY` используется исключительно на сервере и не передаётся клиенту. AI-ответы проверяются Pydantic-схемами; подтверждение фактов и решение по отклику остаются за человеком.

## Установка и запуск

Нужны Node.js 22+, npm и Python 3.10+. Команды выполняются из корня проекта:

```bash
npm install
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp -n .env.example .env
```

Откройте `.env` и вставьте ключ в строку `OPENAI_API_KEY=...`. Не публикуйте этот файл и не помещайте ключ в `NUXT_PUBLIC_*`. При изменении `.env` перезапустите FastAPI. Если ключа пока нет, оставьте значение пустым: приложение продолжит работать, но AI-разбор, AI-интервью и AI-review будут недоступны; интерфейс покажет вопросы на основе правил.

Чтобы назначить **первого администратора**, добавьте в `.env` длинный случайный `ADMIN_BOOTSTRAP_TOKEN` (не менее 24 символов), например сгенерированный командой `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`, и перезапустите API. Зарегистрируйте **отдельный** обычный аккаунт для администрирования, войдите в него и в появившейся панели «Первый администратор FORGE» введите этот секрет. Аккаунт станет администратором; его прежний кабинет бизнеса/команды заменится админ-панелью. Повторное использование секрета после назначения первого администратора запрещено. Дальше администратор выдаёт роли во вкладке «Пользователи и роли». Последнего администратора снять нельзя. В продакшене используйте HTTPS и храните секрет вне публичных файлов.

Учёт AI-затрат работает без дополнительного API: сервер записывает `usage` каждого нового ответа OpenAI. Для `gpt-4.1-mini` применяется тариф $0.40 за 1 млн обычных входящих токенов, $0.10 за кэшированные входящие и $1.60 за исходящие ([официальная страница модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini)). При смене модели задайте в `.env` `OPENAI_INPUT_USD_PER_MILLION`, `OPENAI_CACHED_INPUT_USD_PER_MILLION` и `OPENAI_OUTPUT_USD_PER_MILLION` по её актуальному тарифу. Если тариф неизвестен, стоимость вызова не выдумывается и отмечается как неизвестная. Это локальная **оценка**, не сверка с биллингом OpenAI.

Один терминал:

```bash
npm run dev:all
```

Или два терминала:

```bash
.venv/bin/uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
npm run dev -- --host 127.0.0.1 --port 3000
```

Сайт: `http://127.0.0.1:3000/`. Документация API: `http://127.0.0.1:8000/docs`. Перед запуском `dev:all` остановите другие процессы на портах 3000 и 8000. База создаётся автоматически по пути из `DATABASE_PATH` в `.env`; существующие записи не удаляются при запуске.

## Как проверить: сценарий для жюри

С чистой базой никакие задачи не предзагружены — сценарий создаёт реальные записи:

1. Зарегистрируйте аккаунт роли «Бизнес» и создайте задачу из текста: «Мы получаем много обращений клиентов в разных каналах. Хотим ускорить разбор и подготовить AI-помощника. Пока не знаем, какие данные передать команде и как принять результат».
2. Убедитесь, что компилятор показывает неполную постановку и конкретные ошибки. Ответьте на вопросы интервью, дополните и подтвердите поля Task Pack. При наличии ключа проверьте AI-разбор с цитатами; без ключа будут обозначенные как правило-подсказки вопросы.
3. Запустите Handoff Test, просмотрите пять проверок. Укажите доступ к данным, ответственного за приёмку и критерии, затем запустите тест снова. Опубликуйте задачу.
4. Выйдите, зарегистрируйте аккаунт роли «Команда», найдите опубликованную задачу через каталог и фильтры. Откройте полный Task Pack и отправьте предложение с планом, сроком, ссылкой на прототип (если есть) и вопросами заказчику.
5. Войдите как бизнес, сравните предложение, примите или отклоните его вручную. В кабинете команды проверьте обновившийся статус.
6. Для проверки админки настройте `ADMIN_BOOTSTRAP_TOKEN`, создайте отдельный аккаунт администратора, назначьте его первым администратором. В админ-панели проверьте сводку, вкладки «Пользователи и роли», «AI и токены», «История ролей». При включённом OpenAI совершите новый AI-вызов и обновите панель: появятся фактические токены и оценка затрат.

Автоматические проверки:

```bash
.venv/bin/python -m unittest discover -s backend/tests -v
npm run build
```

## Данные и внешние сервисы

Приложение хранит введённые пользователями данные, журнал ролей и локальный журнал AI-токенов в SQLite. Начальных задач, пользователей и искусственных откликов нет. Единственный внешний сервис — OpenAI API, если вы добавили `OPENAI_API_KEY` в `.env`. Вызовы OpenAI выполняются сервером. Фронтенд не содержит ключа; запросы к OpenAI не нужны для базовой регистрации, публикации, каталога и откликов. Оригинальные декоративные изображения созданы для этого проекта встроенным генератором изображений и оптимизированы в WebP.

## Известные ограничения

- SQLite подходит для локального запуска и пилота; для многосерверной нагрузки потребуется PostgreSQL и отдельная стратегия миграций.
- Журнал AI-вызовов начинается с этой версии: запросы, сделанные до его появления, не восстанавливаются. Ошибочный запрос без ответа `usage` может иметь неизвестную стоимость. Панель показывает только локально записанные вызовы, не общие расходы всего OpenAI-аккаунта.
- Роль администратора сейчас отдельная, а не дополнительная: для неё лучше создать отдельный аккаунт. Первоначальное назначение защищено длинным секретом, но для публичного интернета также необходимы HTTPS, rate limiting и централизованное управление секретами.
- Регистрация и роли реализованы, но для публичного продакшена нужны подтверждение почты, восстановление пароля, rate limiting, аудит и эксплуатационный мониторинг.
- Handoff Test — проверка достаточности постановки, не объективный прогноз качества решения. Без API-ключа работают только детерминированные правила.
- Реальный вызов OpenAI зависит от действующего ключа, доступа к сети, квоты и доступности модели. Автотесты не расходуют API-квоту.
- Деплой пока не выполнен; ссылки на развёрнутую версию нет.
