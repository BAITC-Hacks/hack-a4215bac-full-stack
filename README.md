# FORGE — ясная бизнес-задача для команды

FORGE — веб-платформа для практического хакатона AI Sana. Она помогает бизнесу превратить свободное описание проблемы в проверяемое задание, а командам — понять исходные данные, ожидаемый результат и критерии приёмки до старта работы. Организаторы получают панель для управления ролями и наблюдения за активностью. Это рабочее приложение с аккаунтами и сохранением данных, а не набор демо-экранов.

## Что реализовано

- Публичный лендинг с адаптивной навигацией, орбитальной анимацией этапов вокруг знака FORGE, плавным появлением секций, фотографическими иллюстрациями и поддержкой `prefers-reduced-motion`.
- Регистрация и вход для бизнеса и команд; возврат на лендинг с обоих экранов. Администратора нельзя выбрать при регистрации. Сессии, права доступа и проверка владельца выполняются сервером.
- Кабинет бизнеса: черновики, уточняющие вопросы, редактирование карточки, Task Pack, Handoff Test, публикация и ручное рассмотрение предложений.
- Разбор исходного текста и интервью с помощью OpenAI при наличии ключа. Предположения модели сопровождаются цитатой из исходного текста и **не считаются подтверждёнными**, пока их не проверит автор. Без ключа доступны честно обозначенные вопросы по правилам.
- Readiness Compiler: воспроизводимая оценка до 100 баллов только по подтверждённым сведениям, коды ошибок и предупреждений, конкретный следующий шаг. Низкий балл не скрывает задачу и не запрещает публикацию: замечания остаются видны командам.
- Task Pack из семи секций, источник и статус каждого пункта, история ответов, версия пакета. Handoff Test проверяет пять условий передачи по правилам. При наличии ключей OpenAI и/или NVIDIA NIM добавляются независимые рецензии **только подтверждённых данных**. AI может выявить дополнительную неоднозначность, но не улучшить результат правиловой проверки или выбрать команду.
- Каталог опубликованных задач с поиском и фильтрами, карточка с открытыми замечаниями, профиль команды, предложение с идеей, планом, сроком, необязательной ссылкой на прототип и вопросами заказчику. Бизнес сам принимает, отклоняет или откладывает предложения; подтверждённый этап начисляет команде баллы.
- Администратор видит обычное рабочее пространство, каталог и все предложения (чужие решения — только для просмотра); отдельный пункт сайдбара открывает админ-панель. Можно создавать и редактировать **свои** задачи, назначать роли, смотреть сводку, журнал изменений ролей и журнал AI-вызовов с провайдером, моделью, токенами и локальной оценкой затрат.

## Основной сценарий

1. Бизнес создаёт аккаунт и описывает проблему своими словами. Черновик сохраняется в SQLite.
2. OpenAI, если ключ настроен, предлагает поля и уточняющие вопросы. Автор сверяет предложения с источником, отвечает и подтверждает факты. Без OpenAI этот шаг использует вопросы по правилам.
3. Компилятор показывает полноту и пробелы. Автор дополняет Task Pack: данные, результат, критерии приёмки, контакт, ограничения и порядок взаимодействия.
4. Handoff Test проверяет, сможет ли независимая команда начать работу. При настроенном NVIDIA-ключе модель даёт второе мнение рядом с OpenAI; при недоступности любой модели правила продолжают работать.
5. После публикации команда находит задачу, читает подтверждённый пакет и отправляет предложение. Владелец задачи сравнивает подходы и принимает решение вручную.

## Оценка, AI и границы доверия

Официальный балл рассчитывается на сервере без модели. Контекст и потребность дают до 20 баллов, данные — 20, результат — 15, критерии успеха — 15, ограничения — 10, пользователи — 10, связь с бизнесом — 10. Ошибки `E01–E07`, предупреждения `W02–W07` и статус сборки отражают **полноту постановки**, а не вероятность успеха проекта.

Handoff Test задаёт пять вопросов: ясна ли проблема, указаны ли пользователи, доступны ли данные, определён ли результат и понятна ли приёмка. Сначала вычисляются правила. OpenAI и NVIDIA NIM, если настроены, независимо анализируют ту же подтверждённую карточку; критическое замечание любой рецензии может понизить отдельную проверку. Независимый AI не читает историю интервью, неподтверждённые подсказки и чужие черновики. Результат проверки — рекомендация, не автоматическое решение о победителе.

## Технологии и архитектура

| Слой | Стек | Ответственность |
| --- | --- | --- |
| Клиент | Nuxt 4, Vue 3, JavaScript, CSS | Лендинг, кабинеты, редактор, каталог, админ-панель |
| Сервер | Python, FastAPI, Pydantic | Авторизация, API, права, оркестрация AI |
| Хранение | SQLite | Пользователи, сессии, задачи, ответы, команды, предложения, журнал ролей и AI-токенов |
| AI | [OpenAI Responses API](https://developers.openai.com/api/docs/guides/structured-outputs), [NVIDIA NIM Chat Completions](https://docs.api.nvidia.com/nim/reference/meta-llama-3_3-70b-instruct-infer) | Разбор, интервью и независимая проверка задания |

Маршруты FastAPI — `backend/main.py`; правила и оценка — `backend/domain.py` и `backend/compiler.py`; AI-вызовы и журнал токенов — `backend/ai.py`; схема и небольшие миграции SQLite — `backend/storage.py`. Главный пользовательский поток — `app/pages/index.vue`, панели — `app/components/`. Тёмная тема и движение — `app/assets/rebrand.css`, `landing.css`, `motion.css`. Новые оптимизированные изображения: `public/forge-brief-v2.webp` и `public/forge-collaboration-v2.webp`.

Браузер обращается к FastAPI, но **не получает API-ключи**. Они читаются только сервером из `.env`. NVIDIA NIM используется через OpenAI-совместимый endpoint, но с собственным ключом и отдельной моделью. Ответы моделей проходят проверку структуры и допустимых значений. Все выводы могут ошибаться — подтверждение сведений и выбор команды остаются за людьми.

## Установка и запуск

Нужны Node.js 22+, npm и Python 3.10+. Из корня проекта:

```bash
npm install
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp -n .env.example .env
```

Откройте `.env` и задайте нужные значения:

```dotenv
OPENAI_API_KEY=ваш_ключ_openai
OPENAI_MODEL=gpt-4.1-mini
NVIDIA_API_KEY=ваш_ключ_nvidia
NVIDIA_MODEL=meta/llama-3.3-70b-instruct
```

Можно настроить один ключ, оба или ни одного: основной поток задач работает без внешнего AI. Если меняете `.env`, перезапустите FastAPI. Не размещайте ключи в `NUXT_PUBLIC_*`, Git или браузере. Доступ к NVIDIA NIM и конкретной модели должен быть разрешён вашему NVIDIA-аккаунту; если модель не доступна, замените `NVIDIA_MODEL` на разрешённую в вашей консоли.

Для назначения первого администратора создайте случайный `ADMIN_BOOTSTRAP_TOKEN` длиной не менее 24 символов, например:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Вставьте значение в `.env`, перезапустите API, зарегистрируйте отдельный аккаунт бизнеса или команды и в появившемся баннере введите секрет. После назначения первого админа повторно использовать bootstrap нельзя; дальше роли выдаются в админ-панели. Последнего администратора понизить нельзя. Админ сохраняет доступ к рабочему пространству и может управлять только собственными задачами; решения по чужим предложениям остаются за их владельцами.

Запуск одним терминалом:

```bash
npm run dev:all
```

Или в двух терминалах:

```bash
.venv/bin/uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
npm run dev -- --host 127.0.0.1 --port 3000
```

Сайт: `http://127.0.0.1:3000/`. Документация API: `http://127.0.0.1:8000/docs`. Путь к файлу базы задаётся `DATABASE_PATH` (по умолчанию `.data/forge-live.db`). Запуск создаёт отсутствующие таблицы и добавляет новые колонки без очистки существующих данных.

## Как проверить: сценарий для жюри

1. Откройте лендинг, проверьте движение карточек `01/02/03` вокруг FORGE, прокрутите секции и убедитесь, что «На главную» работает со входа и регистрации. В системном режиме уменьшения анимации постоянное движение отключается.
2. Зарегистрируйте бизнес и создайте задачу из текста: «Мы получаем обращения клиентов из нескольких каналов. Операторы распределяют их вручную и теряют время. Нужен прототип, который поможет сортировать обращения». Проверьте сохранённый черновик, пробелы в оценке и вопросы. При OpenAI-ключе проверьте предложения с цитатами и подтвердите только верные сведения.
3. Заполните Task Pack, запустите Handoff Test, уточните доступ к данным и критерии приёмки. Если заданы оба AI-ключа, итог покажет две независимые рецензии; при отсутствии ключей — только проверку по правилам. Опубликуйте задачу.
4. Зарегистрируйте команду, найдите задачу в каталоге, изучите замечания и отправьте предложение с планом и сроком. Вернитесь в бизнес-аккаунт и примите/отклоните его вручную.
5. Назначьте администратора, откройте обычный каталог, затем «Админ-панель» в сайдбаре. Проверьте пользователей, роли, журнал ролей и AI-токены. Админ может просматривать чужие предложения, но не подтверждать за чужой бизнес этапы.

Автоматические проверки:

```bash
.venv/bin/python -m unittest discover -s backend/tests -v
npm run build
```

Тесты используют отдельную временную SQLite-базу и моки AI, поэтому не расходуют API-квоту и не трогают рабочие записи.

## Данные, интеграции и расходы

Пользователи, задания и предложения создаются самими людьми; стартовых демо-записей нет. Внешние сервисы используются только при заданных ключах: OpenAI для структурирования текста/интервью/Handoff, NVIDIA NIM для второго независимого Handoff-review. AI-журнал хранит фактические токены, возвращённые провайдерами, и статус вызова. Для `gpt-4.1-mini` стоимость считается локально по тарифу $0.40 / $0.10 кэш / $1.60 за 1 млн токенов ([официальная страница модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini)); для другой OpenAI-модели тариф можно задать через `OPENAI_INPUT_USD_PER_MILLION`, `OPENAI_CACHED_INPUT_USD_PER_MILLION`, `OPENAI_OUTPUT_USD_PER_MILLION`. **Стоимость NVIDIA сейчас не оценивается**, потому что тариф зависит от вашего доступа; её токены считаются, но не прибавляются к денежной сумме. Это не официальный биллинг аккаунта.

Изображения `forge-brief-v2.webp` и `forge-collaboration-v2.webp` созданы для FORGE встроенным генератором изображений, затем оптимизированы в WebP. Они декоративные и не содержат пользовательских данных.

## Известные ограничения

- Для публичного продакшена нужны HTTPS, подтверждение почты, восстановление пароля, ограничение частоты запросов, централизованное хранение секретов и мониторинг. Текущая версия рассчитана на локальный/пилотный запуск.
- SQLite удобна для одного сервера; многосерверная нагрузка потребует PostgreSQL и управляемых миграций.
- Handoff Test проверяет полноту и ясность входных сведений, но не качество будущего решения. AI-ответы могут быть неверными или недоступными из-за лимитов/сети; в этом случае остаются детерминированные правила.
- AI-журнал содержит только новые вызовы после включения учёта. Если провайдер не вернул `usage` или тариф неизвестен, денежная стоимость вызова остаётся неизвестной.
- Пока нет публичного деплоя; ссылки на развёрнутую версию нет.
