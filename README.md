# FORGE — от проблемы к практическому проекту

FORGE — платформа для кейса **AI Sana: геймификация практических заданий**. Она помогает бизнесу превратить реальную проблему в понятную задачу для студенческих команд, а командам — найти задачу, предложить решение и получить баллы за подтверждённый прогресс. Работа начинается со свободного описания проблемы; AI помогает выделить факты и задать уточняющие вопросы, но ничего не публикует и не подтверждает за человека.

## Что реализовано

- Регистрация, вход, выход и сохраняемые сессии. Отдельные роли **бизнес** и **команда** с серверной проверкой доступа и владения задачей.
- Личный кабинет бизнеса: создание черновика, AI-анализ описания, AI-интервью, редактирование и публикация Task Blueprint, просмотр и обработка откликов на свои задачи.
- AI-подсказки привязаны к цитате из исходного описания и остаются **неподтверждёнными**, пока представитель бизнеса не проверит их. Если ключ не задан или AI недоступен, черновик сохраняется и может быть заполнен вручную. Синтетические ответы не выдаются за AI.
- Серверный рейтинг готовности задачи 0–100 с прозрачной разбивкой по полям; AI рейтинг не выставляет. Предпросмотр карточки «Глазами команды».
- Личный кабинет команды: профиль и навыки, открытый каталог с фильтрами, отклик от собственного аккаунта, отслеживание статуса откликов и баллов.
- Ручной выбор или отклонение команды бизнесом. После подтверждения этапа выбранной команде начисляется 20 баллов; повторное начисление блокируется.
- Постоянное хранение аккаунтов, сессий, задач, команд и откликов в SQLite. **Демо-аккаунты и предзаполненные задачи не создаются.**

## Как работает решение

1. Представитель бизнеса регистрируется и описывает проблему своими словами.
2. Сервер сохраняет черновик. При настроенном OpenAI API анализирует текст и предлагает название, категорию, поля с цитатами-основаниями и 3–5 уточняющих вопросов.
3. Бизнес отвечает на вопросы, проверяет подсказки, при необходимости исправляет поля и подтверждает их. При изменении поля подтверждение снимается. Рейтинг пересчитывается по подтверждённой информации.
4. Бизнес публикует задачу. Зарегистрированная команда видит её в каталоге и отправляет идею, план, срок и ссылку на прототип.
5. Владелец задачи вручную принимает или отклоняет предложение. Подтверждённый этап увеличивает счёт команды.

### Рейтинг готовности

| Сведения | Баллы |
| --- | ---: |
| Контекст и потребность | 20: по 10 за каждое поле |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 10: по 5 за каждое поле |

Баллы начисляются только за содержательные **подтверждённые** поля. Уровни: 0–39 — «Черновик», 40–69 — «Рабочая», 70–89 — «Готовая», 90–100 — «Приоритетная». Это метрика полноты постановки, не оценка качества будущего решения. Формула находится в `backend/domain.py`.

## Технологии и архитектура

- **Фронтенд:** JavaScript, Vue 3, Nuxt 4, HTML, CSS.
- **Бэкенд:** Python 3.10+, FastAPI, Pydantic, SQLite.
- **AI:** официальный Python SDK OpenAI и Responses API со структурированным выводом; модель настраивается через `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`). Вызовы и проверки ответов — в `backend/ai.py`.
- **Аутентификация:** пароли хэшируются PBKDF2-SHA256 с индивидуальной солью; сервер хранит хэши непрозрачных сессионных токенов, а не сами токены.

```text
Браузер → Nuxt (:3000) → HTTP JSON + Bearer token → FastAPI (:8000)
                                                   ├─ auth + роли → SQLite
                                                   ├─ задачи + рейтинг → SQLite
                                                   ├─ отклики + решения → SQLite
                                                   └─ AI-анализ/вопросы → OpenAI Responses API
```

Ключ OpenAI используется **только на сервере**. AI не выбирает команды, не присуждает баллы и не превращает свои предположения в подтверждённые факты.

## Установка и запуск

Нужны Node.js 22+, npm и Python 3.10+. Выполняйте команды в корне проекта.

1. Установите зависимости фронтенда:

   ```bash
   npm install
   ```

2. Создайте окружение Python и установите зависимости API:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r backend/requirements.txt
   ```

3. Создайте `.env`, если его нет: `cp .env.example .env`. В проекте уже подготовлен локальный `.env` с пустым значением. Откройте файл и вставьте ключ **после знака равенства**:

   ```dotenv
   OPENAI_API_KEY=ваш_ключ_здесь
   OPENAI_MODEL=gpt-4.1-mini
   DATABASE_PATH=.data/forge-live.db
   FRONTEND_ORIGIN=http://localhost:3000,http://127.0.0.1:3000
   ```

   Не добавляйте кавычки и не коммитьте `.env` — он указан в `.gitignore`. После изменения ключа **перезапустите FastAPI**. Без ключа все не-AI функции работают, а `/api/health` возвращает `ai_configured: false`.

4. Запустите API в первом терминале:

   ```bash
   source .venv/bin/activate
   uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
   ```

5. Запустите Nuxt во втором терминале:

   ```bash
   npm run dev -- --host 127.0.0.1 --port 3000
   ```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). API: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health); схема: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Для другого адреса API задайте `NUXT_PUBLIC_API_BASE`, а для другого адреса фронтенда — `FRONTEND_ORIGIN`.

## Как проверить решение

1. Зарегистрируйте аккаунт с ролью **«Бизнес»**. Введите, например: «Сотрудники вручную распределяют обращения клиентов между отделами, поэтому ответ часто задерживается». Создайте Blueprint.
2. Если ключ настроен, проверьте AI-поля и цитаты, ответьте на вопросы. Если ключа нет, заполните поля карточки вручную. Подтвердите несколько полей и убедитесь, что рейтинг изменился. Опубликуйте задачу.
3. Выйдите и зарегистрируйте второй аккаунт с ролью **«Команда»** и навыком «Python». Найдите задачу в каталоге. Идея: «Создадим классификатор обращений с проверкой оператором»; план: «Разметим примеры, соберём прототип, сравним точность с ручной сортировкой»; срок: «14 дней»; тестовая ссылка: `https://example.com/prototype`.
4. Вернитесь в бизнес-аккаунт. В «Предложениях» выберите свою задачу, примите предложение и подтвердите этап.
5. Снова войдите как команда. В «Моих откликах» проверьте статус, а в профиле — начисленные 20 баллов.

Автоматические проверки:

```bash
source .venv/bin/activate
python -m unittest discover -s backend/tests -v
npm run build
```

Тесты подменяют внешний AI-вызов и проверяют обработку его структурированного результата; настоящий запрос к OpenAI можно выполнить только с действующим ключом.

## Данные и интеграции

- Все рабочие данные вводятся пользователями и хранятся локально в `.data/forge-live.db`. При первом запуске база пуста. Старый файл `.data/forge.db` от прототипа не используется и не удаляется.
- В OpenAI передаются текст задачи и уже введённые поля для анализа/уточнений. Не вводите персональные или конфиденциальные данные без соответствующего разрешения.
- Внешний сервис — только OpenAI API; для базового сценария без AI внешние интеграции не нужны. Google Fonts используется для типографики интерфейса.

## Ограничения текущей версии

- Прямой запрос к OpenAI не проверен без предоставленного ключа; доступность модели, квоты и расходы зависят от аккаунта владельца ключа.
- SQLite и локальные сессии подходят для одного экземпляра приложения; для публичного многосерверного развёртывания нужны управляемая БД, HTTPS, защита от перебора паролей, восстановление пароля и мониторинг.
- Нет встроенного обмена файлами, чата между бизнесом и командами, модерации контента и проверки реальности внешних ссылок.
- Ссылка на развёрнутую версию пока отсутствует: развёртывание не выполнялось.
